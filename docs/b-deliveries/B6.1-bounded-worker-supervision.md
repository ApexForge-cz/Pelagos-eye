# B6.1 bounded Pelyr worker supervision

**Issue:** [#44](https://github.com/ApexForge-cz/Pelagos-eye/issues/44)

**Branch:** `ais/bounded-worker-supervision`

**Owner:** Developer B

## Scope

This delivery adds one backend-only, bounded Pelyr `/v1` worker. It validates the
provider handshake and connection-scoped licence directory, submits only the fixed
Gulf of Finland `fields=position` subscription, passes accepted position frames to
the B5 normalizer, and supervises continuity. It does not add a public route,
browser connection, persistence, replay, client fan-out, backpressure, dynamic
bounds, export, or UI.

## Fixed operating boundary

```text
west=23.50, south=59.50, east=26.50, north=60.50
fields=position
subscription id=oceanscope-gulf-of-finland
```

The worker accepts only a provider `subscribed` response whose effective bbox and
fields exactly match that request. Runtime limits are validated from `welcome`;
`0` retains Pelyr's documented meaning of unlimited and is not converted to a
zero-capacity claim. Source metadata is rebuilt per connection. Source `0`,
`NOASSERTION`, empty attribution, duplicate ids, and unknown frame licences cannot
publish a position.

## State and timing

The supervisor uses `DISCONNECTED -> CONNECTING -> CONNECTED` and
`CONNECTED/CONNECTING -> RECONNECTING`, with cancellation or clean shutdown
ending in `DISCONNECTED`. It never starts a parallel connection attempt.

| Concern | Bound |
| --- | --- |
| WebSocket open | 10 s |
| Welcome | 5 s |
| Initial subscribe | min(provider deadline, 5 s) |
| Subscription confirmation | 5 s |
| Heartbeat deadline | 45 s for the documented 20 s heartbeat |
| Close | 5 s |
| Retry delays | 1, 2, 4, 8, 16, 30 s plus bounded +/-20% jitter |
| Retry reset | after 60 s stable connectivity |

Every continuity break emits a non-replayable `stream.gap`. Status and gap objects
contain only bounded reason/state/metric fields. They do not contain API keys, raw
provider frames, MMSI values, coordinates, or exception text. Provider loss,
`feed=stalled`, malformed control frames, rejection, invalid licences, socket close,
and heartbeat timeout all become explicit failure states with `DATA UNAVAILABLE`.

## Security and retention

`PELYR_API_KEY` is read only from server-side environment injection and is passed in
the Authorization header. It is never included in the WebSocket URL, status objects,
worker representation, or transport logger output. Accepted positions exist only at
the injected sink; B6.1 creates no storage or cache.

## Tests and verification

The focused worker tests use mocked transport and fictional values explicitly labeled
`TEST DATA`. They cover welcome/limits/source validation, fixed subscription
enforcement, B5 normalization, heartbeat/feed/loss handling, provider rejection,
malformed frames, licence rejection, timeouts, capped serial retry, cancellation,
task cleanup, key/raw-frame non-leakage, and no zero-filled fallback.

Commands run locally:

## Limitations and next boundary

The worker is not registered in the FastAPI lifespan and intentionally has no public
consumer yet. B6.2 must be reviewed separately before adding in-memory fan-out,
coalescing, queue limits, or product delivery. Phase 4 remains `Planned`; this PR
does not claim live coverage, continuity, completeness, or production availability.
