## Scope and local security boundary

The API container receives optional, blank-safe `PELYR_API_KEY` and the fixed local
AIS Origin allowlist `http://localhost:4173,http://localhost:5173`. The key is not
a build argument, Web environment value, browser URL, or client message. Whitespace
keys retain the existing Settings normalization and do not construct a worker.

The local Compose Web service shares the API network namespace. Nginx connects to
`127.0.0.1:8000`; the API owns the loopback-bound host ports 8000 and 4173. Host
8000 maps to Nginx's API-only listener on 8081, while host 4173 maps to the Web
listener on 8080. This also supports host Vite -> published API without treating
a Docker NAT peer as loopback. The API process and internal healthcheck remain
on 8000; the API-only Nginx listener passes every path through without SPA fallback. The
Compose-only Uvicorn command disables proxy-header address rewriting. Nginx still
preserves Host, Origin, forwarded address and protocol. Existing HTTP routes and
the SPA use the same backend and paths. The existing backend Origin/loopback
checks, production fail-closed rule, event contract, provider and gateway are unchanged.

This explicitly trusts the local machine and processes in the Compose network;
Origin is not authentication. It does not authorize remote or production deployment.
Do not replace the local binding or enable trusted forwarded headers to expose a
public feed. The shared namespace also means recreating API requires recreating
Web: use `docker compose ... up -d --force-recreate api web`, not an API-only
container replacement. For a managed restart use `docker compose ... restart api`;
`depends_on.api.restart: true` restarts Web after its namespace owner. Do not
restart both services concurrently or use a direct Docker API-only restart.
Daemon-triggered recovery is not orchestrated by this dependency flag; if it
occurs, recreate API and Web together before repeating acceptance.

Design was posted before coding in issue comments 6559688274 and 6559947911. Developer A reviews
this topology and its acceptance evidence before merge.

## Reproducible checks

Run commands from the repository root with the API environment's Python available.
On Windows, it is `apps/api/.venv/Scripts/python.exe`. Do not echo keys, dump a
real-key Compose model, run credential-bearing `docker inspect`, or commit raw
frames, identifiers, coordinates, provider logs, or screenshots containing them.

### Configuration and syntax

The focused test uses an isolated temporary env file, configuration-only `TEST DATA`
placeholders, a sanitized Docker CLI config, and Docker's own Compose JSON parser.
It cannot load the real project `.env`. It checks unset, empty, whitespace and
placeholder keys, both origins, server-only injection and loopback topology:

```text
apps/api/.venv/Scripts/python.exe -m pytest apps/api/tests/test_live_ais_runtime.py -q
```

The integration-marked Compose checks require the Compose CLI, not the daemon.
If unavailable, pytest reports an explicit skip; that is not runtime acceptance.

### Disposable no-key Docker stack

Use a separate project (for example `oceanscope-b63-smoke`) and an ignored local
environment file containing test-only database settings and `PELYR_API_KEY=`.
Unset inherited `PELYR_API_KEY` and `OCEANSCOPE_*` overrides for this invocation so
the shell cannot accidentally supply a real credential or database endpoint.
Keep ports 8000 and 4173 free; never stop an unrelated process to obtain them.

```text
docker compose --env-file <test-only-env-file> -p oceanscope-b63-smoke -f infra/compose.yaml config -q
docker compose --env-file <test-only-env-file> -p oceanscope-b63-smoke -f infra/compose.yaml up --build -d --wait
docker compose --env-file <test-only-env-file> -p oceanscope-b63-smoke -f infra/compose.yaml exec -T web nginx -t
apps/api/.venv/Scripts/python.exe scripts/smoke_live_ais_runtime.py --seconds 75
```

The smoke script checks API JSON readiness directly on port 8000. Nginx `/health`
is only proxy liveness, and a SPA HTML response is not API readiness. It probes
missing/null/unapproved Origins using ordinary requests, then
holds an approved connection beyond Nginx's 60-second idle-read window. Uvicorn
WebSocket pings keep an otherwise idle no-key connection alive. It verifies an
unavailable/OFFLINE initial snapshot and status, no observations, fixed coverage,
strict per-epoch sequence order, and clean client close.

Start the existing Vite development server on localhost:5173 against the same
local API, then run:

```text
npm run dev --workspace @oceanscope/web -- --host localhost --port 5173 --strictPort
apps/api/.venv/Scripts/python.exe scripts/smoke_live_ais_runtime.py --url ws://localhost:5173/live-ais/ws --origin http://localhost:5173
```

Repeat the checks after an API process restart. If the API container is recreated,
recreate both API and Web as described above, then check again. Verify `/`, a SPA
deep link, existing HTTP API routes, and Nginx liveness still respond appropriately;
assert response content, not just HTTP 200. Missing database data is not a proxy
failure and must not be replaced with fixtures.

Stop only this disposable project with `down --volumes --remove-orphans` after
checking its project name. Do not remove unrelated containers or volumes.

### Optional project-lead-supplied real key

This task does not create, retrieve, or require a credential for ordinary tests.
When the lead explicitly supplies a local server key, use a separate local run
with that key only in the API environment, then:

```text
apps/api/.venv/Scripts/python.exe scripts/smoke_live_ais_runtime.py --mode live --seconds 60
apps/api/.venv/Scripts/python.exe scripts/smoke_live_ais_runtime.py --url ws://localhost:5173/live-ais/ws --origin http://localhost:5173 --mode live --seconds 60
```

The tool validates the existing v1 schema, snapshot-first ordering, epoch/sequence
rules, gap-to-snapshot recovery, fixed Gulf of Finland bounds, current positions,
and nonblank attribution. It keeps no payload history and prints only aggregate
counts and fixed check messages. No observations in the bounded window is
incomplete live evidence, not a successful real-data acceptance. Network and
validation errors are sanitized instead of printing their input/response bodies.

Developer A separately verifies actual browser rendering, attribution, selection,
disconnect/gap/stale/empty/no-coverage presentation and bounded rendering/memory.
Check worker cancellation and in-memory purge with existing backend regressions;
no persistent AIS record, track, replay, query or export is introduced here.

### Runtime evidence boundary

The unrelated `oceanscope-issue16` service already occupied host port 8000 and was
left untouched. The disposable `oceanscope-b63-smoke` project therefore published
its API proxy on loopback port 18000, while Web and source Vite used 4173 and 5173.
A temporary Vite configuration imported the unchanged real configuration and
changed only its proxy target port to 18000. The default 8000 mapping was checked
with Docker's Compose parser, rather than taking over the unrelated service.

Because the complete Web image currently fails to build as described below, the
runtime checks used the **same official** `nginxinc/nginx-unprivileged:1.29-alpine`
runtime base with the actual Nginx configuration and locally built production
assets mounted read-only. This proves the running proxy and shared-namespace
behavior; it is **not** acceptance of the complete Dockerfile build.

The ignored test override uses only these differences from the real Compose file:

```yaml
# TEST DATA acceptance override; paths are relative to infra/compose.yaml.
services:
  api:
    ports: !override
      - "127.0.0.1:18000:8081"
      - "127.0.0.1:4173:8080"
  postgres:
    ports:
      - "127.0.0.1:15462:5432"
  web:
    image: nginxinc/nginx-unprivileged:1.29-alpine
    build: !reset null
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ../apps/web/dist:/usr/share/nginx/html:ro
```

Actual smoke commands used `--ready-url http://localhost:18000/health/ready` and
`--seconds 75` for each of the two socket URLs above. The API container's key was
asserted absent without printing its value. No real provider connection was made.
HTTP error responses were checked as `application/problem+json` where appropriate:
the empty application database returned 503 for `/ports`, while missing required
query parameters returned 422 for earthquakes/forecast. These are preserved API
responses, not Nginx or fabricated-data fallbacks.

The first concurrent API/Web restart failed to restore the shared namespace.
Adding `depends_on.api.restart: true` and using a managed `restart api` fixed the
ordering. The passing retest used a bounded 10-second handshake and 90-second
recovery window; an initial two-second retry timeout was too short in this host
environment. Runtime checks and restarts must be sequenced, not run concurrently.
