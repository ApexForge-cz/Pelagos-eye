## Scope

This delivery consumes B6.1's provider-neutral positions and bounded worker status/gap
events. It adds in-memory latest state, same-MMSI coalescing, explicit continuity recovery,
bounded client fan-out, and the fixed same-origin `/live-ais/ws` product transport. It does
not add a browser-to-Pelyr connection, persistent AIS storage, replay, dynamic bounds,
tracks, arbitrary vessel lookup, export, or a public vessel-data API.

The public contract in `api/contracts/live_ais.py` is unchanged.

## Queue and latest-state design

- The B6.1 synchronous position sink uses `put_nowait` on one 2,048-event ingress queue.
  A full queue records dropped positions and schedules a `server_backpressure` gap rather
  than blocking provider reads or silently skipping observations.
- Worker status and gap events are bounded typed objects handled directly on the same event
  loop. Raw provider frames and exception text never enter the gateway.
- Same-MMSI positions coalesce for at most 250 ms. Latest wins, and public sequences are
  assigned only after coalescing.
- Latest state is memory-only, expires by local monotonic receipt age after five minutes,
  and is capped at 10,000 MMSI. Snapshots contain at most 5,000 positions and set
  `truncated=true` after a capacity or continuity loss.
- Every client has an independent 256-event queue and contiguous sequence. This prevents
  one slow client from creating false sequence gaps for healthy clients. At most 25 clients
  are registered.

## Snapshot, epoch, and recovery behavior

- Every client receives `vessel.snapshot` first, followed by the current `stream.status`.
- A validated provider epoch becomes the public UUID epoch. Reconnect/source-epoch change
  clears old latest state, resets each client sequence, and sends a new snapshot before
  incremental events.
- Provider loss clears latest state and sends a non-replayable `provider_disconnect` gap
  followed by an unavailable empty snapshot.
- Server ingress/capacity loss sends `server_backpressure` plus a truncated replacement
  snapshot. No completeness claim is made.
- On a client queue overflow, queued obsolete events are discarded, sequence resumes after
  the last event actually handed to that client, and `client_backpressure` plus a replacement
  snapshot are queued. A second overflow before recovery completes disconnects the client.
- `AVAILABLE` with an empty covered snapshot, `NO COVERAGE`, and `DATA UNAVAILABLE` remain
  distinct contract states. Positions are never interpolated or zero-filled.

## Route, origin, and session boundary

- The only product route is `/live-ais/ws`; there is no public snapshot GET, cursor, replay,
  query, or export endpoint.
- Missing, `null`, malformed, or unapproved `Origin` values are rejected before WebSocket
  acceptance. The allowlist is configured separately from CORS with
  `OCEANSCOPE_LIVE_AIS_ORIGINS`.
- Development requires both a loopback Origin and a loopback client address. This is a
  local demo boundary, not authentication.
- Production always fails closed with `production_session_required`, even for a configured
  Origin, until Developer A accepts a real product session, proxy topology, and traffic
  policy. Client-sent messages are rejected.

## Lifecycle and shutdown

FastAPI constructs one gateway. It starts exactly one Pelyr worker only when the server-side
`PELYR_API_KEY` is configured. A missing key keeps the API healthy and sends an explicit
`DATA UNAVAILABLE` snapshot/status. Shutdown cancels and awaits the worker, stops the
consumer, wakes/disconnects clients, and purges ingress, pending coalescing, latest state,
and client queues.
