## Scope and deliverables

Consume B6.1's normalized positions, worker status, and gap events for only the
fixed Gulf of Finland box (`west=23.50`, `south=59.50`, `east=26.50`,
`north=60.50`, WGS 84; `fields=position`). Build bounded in-memory latest state,
same-MMSI coalescing, and product-only snapshot/position/status/gap delivery using
the accepted provider-neutral v1 contract. Wire exactly one worker into app
lifecycle only when a server-side key is configured; without a key, the API stays
healthy while AIS reports `DATA UNAVAILABLE`. No browser-to-provider connection.

- Expire latest positions after five minutes, cap state at 10,000 MMSI, cap snapshots
  at 5,000 with `truncated=true`, and purge state/queues at shutdown. Persist none.
- Bound ingress to 2,048 events, each client queue to 256, and clients to 25.
  Coalesce same-MMSI updates within at most 250 ms before assigning a public
  sequence. On provider loss or overflow emit a non-replayable gap followed by a
  new snapshot. If a slow client cannot receive both, disconnect it. Never silently
  claim complete coverage after truncation or loss.
- New clients get a snapshot first. Use a new epoch after reconnect/source changes;
  increment sequence monotonically within an epoch. Distinguish an available empty
  box, `NO COVERAGE`, and `DATA UNAVAILABLE`. Do not interpolate positions or replay.
- Enforce Developer A's reviewed origin/session and anti-extraction policy from
  `docs/37-live-ais-product-transport.md`: reject missing/unapproved Origin, limit
  unauthenticated exposure to loopback development, and fail closed in production
  until a real session and deployment policy are accepted. Existing CORS alone is
  insufficient for WebSocket security.
- Record bounded-cardinality queue, coalescing, rejection, gap, and latency metrics
  without MMSI, position, credentials, or raw frames in logs or metrics.
- Include mocked `TEST DATA` tests for expiry, overflow, coalescing, disconnect,
  cancellation, missing key, client limits, origin rejection, slow clients, and
  no-persistence behavior. Supply burst/load evidence for memory (128 MiB target),
  CPU, latency, queue high-water marks, and message size; do not claim capacity
  from budget numbers alone.
