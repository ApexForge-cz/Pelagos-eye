## 1. 使用说明与变更原则

本文件不是对 v2.1 的替代，而是从 Phase 4 开始的负责人增量执行层。已有阶段定义、数据真实性规则、来源状态、覆盖边界、Developer B 的所有权和迁移纪律继续有效。新增内容只有在对应阶段验收证据存在后才能标记为完成。

### 双人协作规则

- **Developer A / 项目负责人：**新增产品流程、命令中心布局、Cesium 或 Three.js 数字地球、MapLibre 二维地图、交互状态、可视化编码、前端性能、跨模块集成、演示与发布文档。
- **Developer B / 数据与平台工程师：**原有 AIS provider、采集 worker、去重验证、Redis/PostGIS、WebSocket、历史数据、聚合服务、后端数据测试和性能流水线不迁移、不重写。
- **共享合同先行：**A 可以独立推进 UI 与渲染 mock shell，但只能使用 `TEST DATA` 或真实 API 合同，不得在生产代码中生成假船、假航班、零填充 KPI 或使用 `Math.random()`。
- **当 B 不在：**负责人只在已批准的 contract、repository、service 边界内做集成与前端工作；涉及数据库 schema、provider 协议、迁移或新外部源时，记录 proposal，等待复核。
- 所有外部数据界面必须显示 `LIVE`、`CACHED`、`DELAYED` 或 `OFFLINE`，并同时显示 coverage、effective time、source、unit 和 warning。

## 2. 视频关键帧分析结论

视频约 1 分 50 秒，1280 x 592，约 30 fps。已按约 10 秒间隔抽取关键帧，并结合用户提供的静态截图观察。以下是可转化为产品需求的稳定行为，不把视频中的数字、航班数或告警数当作 OceanScope 真实数据。

| 观察对象     | 视频中反复出现的表现                                                      | OceanScope 可实施的产品要求                                                                       |
| ------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 中央数字地球 | 球体占据主视区，亚洲与中国视角切换；有地形/卫星纹理、边界、路径和高亮区域 | 55%-65% 主视区；真实 WGS 84 数据；纹理与业务叠加分层；选区与镜头状态可恢复                        |
| 时间与运动   | 地球自转、镜头旋转、地区聚焦、昼夜明暗变化                                | 自转开关、暂停、速度档位、昼夜 terminator、镜头过渡和 reduced-motion 降级                         |
| 地理叠加     | 蓝色边界、黄色/青色弧线、光束、节点标签、点状轨迹                         | 每类图层都有数据来源、单位、coverage、LOD、交互和无障碍文本；光束只表达关系，不表达未经证实的风险 |
| 右上二维地图 | 小型世界地图显示当前区域与路线概览                                        | Overview map 与主球体双向联动；矩形范围、视口、选区和数据覆盖明确                                 |
| 左侧分析栏   | 实时航线动态、环图、趋势面积图、热门航线表                                | 改为真实数据绑定组件；缺数据显示 `NO COVERAGE` 或 `DATA UNAVAILABLE`，不显示 0 代替               |
| 右侧状态栏   | 全球统计卡片、趋势环图、告警条目                                          | 拆分 observed、derived、model data；显示时间、来源、状态和解释入口                                |
| 底部指标     | 航班统计、机场运行、天气、燃油、告警等多个卡片                            | OceanScope 只保留海事/海洋模块；航空作为下一个版本预留，不混入当前海事 KPI                        |

### 视觉结论

可借鉴的是信息编排和状态切换，不是把航空仪表盘原样搬入海事系统。OceanScope 的视觉目标为 calm, map-first, dark maritime：低饱和深色底、青蓝主强调、少量橙红状态色、可关闭的微光与动画；任何效果不得遮盖轨迹、标签、误差、覆盖范围或来源。

### 负责人独立工作清单

- **可以独立：**React/TypeScript 组件拆分、Three.js/Cesium/MapLibre 渲染器适配、镜头与交互状态、图层开关、图表布局、文案、无障碍、视觉回归。
- **可以先行：**以 typed contract 和 `TEST DATA` 开发页面骨架，所有测试数据显式标记 `TEST DATA`，不能进入生产配置。
- **必须等待或提交 proposal：**新增 provider、扩大历史 AIS 覆盖、数据库迁移、改变缓存语义、引入航班生产数据、声称全球实时覆盖。
- **每次阶段完成：**运行 lint、type check、相关单测、Playwright 或视觉检查、`git diff --check`，并更新 risk、decision、status 文档。

## 4. 高级数字地球设计合同

数字地球是本次升级的核心，但真实感必须来自真实地形、海陆纹理、光照和正确空间定位，而不是装饰性粒子。建议采用 CesiumJS 作为高质量地球候选，Three.js 作为已安装的可控 fallback；选型在 Phase 3 渲染 POC 中用同一数据集与性能基线验证。

| 能力           | 实现建议                                                                 | 数据/真实性边界                                                           | 降级方案                         |
| -------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------- | -------------------------------- |
| 地形凹凸       | Cesium terrain provider 或经验证的 DEM tiles；Three.js 使用法线/高度纹理 | 地形必须标注 source、resolution、vertical datum；不得把海图深度当陆地高程 | 无地形时使用平滑球体并显示层状态 |
| 海陆与卫星纹理 | 分层 imagery provider，支持亮/暗主题与缓存                               | 记录 provider、时间、版权和缓存年龄；不可伪造云海                         | 低清纹理或纯色海陆层             |
| 昼夜           | 太阳位置计算 + terminator shader；UTC 内部，显示时区在边界转换           | 光照是模型化视觉层，不代表气象实况                                        | 静态光照与文本时区               |
| 自转           | 基于 UTC 的可控旋转；暂停、速度 0.25x/1x/4x                              | 不影响经纬度数据和查询窗口                                                | 不支持 WebGL 时保持静态球体      |
| 云层           | 透明云纹理或天气 tiles，单独图层和开关                                   | 若是模型数据必须标 `MODEL DATA`；若无实时云源显示不可用                   | 关闭云层，不用假云覆盖           |
| 光束/弧线      | 从真实点位或航线关系生成，宽度和颜色固定语义                             | 不可把光束数量当吞吐量；箭头需有方向来源                                  | 普通线段                         |
| 标注           | 碰撞检测、LOD、选中优先、中文/英文切换                                   | 标签来自港口/船舶/事件实体，显示实体时间与来源                            | 侧栏列表和可访问文本             |

### 建议的图层顺序

底色与星空 -> 海陆/卫星纹理 -> 地形 -> 云层 -> 昼夜遮罩 -> 港口/区域边界 -> 船舶点与轨迹 -> 环境/事件层 -> 光束与选中高亮 -> 标签与 HUD。

每层都应能单独关闭，并在 Source Lens 中查看来源、更新时间、覆盖与质量标记。

## 5. 交互与信息架构

| 区域                   | 内容                                           | 交互与验收                                                     |
| ---------------------- | ---------------------------------------------- | -------------------------------------------------------------- |
| 顶部命令栏             | 项目名、UTC/本地时间、数据状态、全局搜索、设置 | 不放未经来源的总数；状态使用文字 + 颜色；窄屏可折叠            |
| 左侧分析栏             | 实时 AIS、区域/港口、趋势、来源摘要            | 选择区域后所有组件联动；空结果和 unavailable 分开              |
| 中央主视图             | 3D 地球或 2D 地图，船、轨迹、港口、环境、事件  | 键盘、鼠标、触摸；相机状态可分享；reduced-motion 关闭过渡      |
| 右侧 intelligence rail | 选中对象详情、证据、风险指标、时间线           | 先显示 observation，再显示 derived/model；指标旁显示单位和时间 |
| 右上 overview map      | 全局范围、当前相机框、覆盖范围                 | 点击 overview 改变主视图；主视图变化同步 overview              |
| 底部 dock              | 图层、时间轴、对比、导出、帮助                 | 图标按钮带 tooltip；文本命令使用 icon + label；不堆叠卡片      |

### 数据状态标签

来源状态仅使用 `LIVE`、`CACHED`、`DELAYED`、`OFFLINE`；内容标签另行使用 `NO COVERAGE`、`MODEL DATA`、`DERIVED`、`TEST DATA`。禁止把 `NO COVERAGE` 渲染为 0，禁止把 `CACHED` 渲染为 `LIVE`。

### 可访问性与响应式

所有颜色都有文本或图标辅助；地图有列表化替代表示；动态自转、粒子和光束遵守 `prefers-reduced-motion`；标签在移动端转为侧栏列表；按钮尺寸稳定，不因中文标签换行而改变布局。

## 6. API、数据和航空预留

当前版本只扩展海事能力。用户要求的航空系统作为下一版本预留，不把航空接口混入当前海事模块，也不在没有核验官方文档、条款、覆盖和 API key 之前承诺接入。

### 航空预留区设计

| 位置       | 预留内容                                                                                                                        | 本版本行为                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 路由/模块  | Future Air Operations 或 Aviation Overview                                                                                      | 只显示 `Coming in next version` / 计划中，不渲染假航班   |
| 数据合同   | `flight_id`、`callsign`、`origin`、`destination`、`position`、`altitude`、`velocity`、`observed_at`、`source_state`、`coverage` | 先写 typed contract 和 provider proposal，不接入生产数据 |
| 仪表盘位置 | 右侧或底部独立航空 rail，可切换，不与海事 KPI 混算                                                                              | 保留空状态位和布局测试，不显示 0 或虚构数量              |
| 数量目标   | 先选择足够多但有明确覆盖边界的区域/航路，优先官方或授权 provider                                                                | 不承诺全球覆盖；必须显示区域、采样、时间与限额           |
| 入口       | 模块开关、权限/条款、来源详情                                                                                                   | 入口可见但标记 `PLANNED` / `NO COVERAGE`                 |

### GeoVis Earth 参考边界

用户提供的 `online.geovisearth.com/browser` 作为交互与视觉参考，用于观察地球浏览、地形、影像和图层组织方式。它不是默认数据源，也不是 OceanScope 的授权证明。正式集成前必须核验官方 API、许可、归因、速率限制、商业/非商业条款、离线缓存和数据覆盖；禁止直接抓取页面、绕过限制或把其瓦片当作已批准生产依赖。

### 个人每日检查

- **开始前：**`git status`、当前分支、允许路径、未提交变更、依赖和 provider 条款。
- **开发中：**保持 handler thin、业务逻辑在 service、数据库在 repository/provider；不跨所有权重写 B 的模块。
- **结束前：**lint、type check、相关 tests、`git diff --check`、浏览器截图、来源状态和文档同步。
- **提交前：**检查密钥、原始受限数据、缓存、临时视频帧和构建产物没有进入 Git；更新 risk register 与 decision log。

## 8. 验收矩阵

### 完成定义

只有当功能、真实数据合同、错误/空状态、来源与新鲜度、测试、性能、无障碍、文档和回滚路径同时具备时，才可从 Planned 变为 Implemented。演示视频或设计稿本身不能作为生产功能验收证据。
